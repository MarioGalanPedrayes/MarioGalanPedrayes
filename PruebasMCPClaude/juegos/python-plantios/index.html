Cómo se juega

    
    
      
  1. Arriba ves la pieza actual y las dos siguientes. Pulsa una casilla vacía del huerto para colocar la actual.
    2. 
      
  2. Si, al colocarla, forma con sus vecinas (arriba, abajo, izquierda o derecha; las diagonales no cuentan) un grupo de 3 o más piezas iguales, todo el grupo se funde en una pieza del nivel siguiente en la casilla donde la pusiste.
    3. 
      
  3. Un grupo de 5 o más es un injerto doble: sube dos niveles.
    4. 
      
  4. La pieza nueva puede fundirse a su vez con otras iguales de alrededor: es una cadena.
    5. 
      
  5. La savia es un comodín: cuenta como cualquier nivel para completar un grupo y se gasta en la fusión. Si no completa ninguno, se queda esperando en su casilla.
    6. 
      
  6. Las piedras ocupan casilla y se deshacen solas cuando una fusión ocurre pegada a ellas.
    7. 
      
  7. El cesto guarda una pieza. Una vez por turno puedes cambiar la pieza actual por la del cesto; si está vacío, la actual se guarda y llega la siguiente. Cambiar no cuenta como turno.
    8. 
      
  8. Ganas cuando crías la pieza objetivo del nivel. Pierdes si el huerto se llena. Deshacer quita la última acción, así que una jugada mala no es el final.
    9. 
      
  9. La referencia son los turnos que gasta el programa para ganar esa misma partida. Tres estrellas hasta un 15 % por encima, dos hasta un 50 %, una si ganas. Las pistas (3 como máximo) limitan la nota a dos estrellas.
    10. 
      
  10. El reto diario es la misma sucesión de piezas y piedras para todo el mundo ese día (nivel Huerto) y cuenta para la racha. En Práctica las piezas son aleatorias y no afectan a las estadísticas.
    11.

    Qué se busca con esta página
    
    
    Esta práctica quiere mostrar que un juego de fusión completo, con un jugador automático incluido, puede tener toda su lógica en Python y publicarse como web estática sin servidor. El HTML, el CSS y un poco de JavaScript solo dibujan el huerto y avisan a Python de cada pieza que colocas.
    
    
    También es un ejercicio de diseño sobre lo que funciona hoy en los juegos web: sesiones de pocos minutos, una sola acción por turno (elegir una casilla), un reto que es el mismo para todos cada día y un resultado que se puede compartir sin estropearle nada a nadie. Los informes del sector de 2026 sitúan a los puzles y a la mezcla de «fusionar» con otros géneros entre lo que más crece en juegos casuales.
    
  
    

  
    
    
    Cómo está hecho
    
    
      
      
    • codigo.py contiene las reglas: las piezas y las piedras de cada partida, la colocación, las fusiones en cadena (con búsqueda de grupos conectados), la savia, el cesto, deshacer, las pistas, las estrellas, el texto para compartir y la racha de días.
      • 
      
    • Siempre se puede ganar: cada partida se comprueba con un jugador automático que mira las casillas libres y las piezas iguales que quedan juntas. Solo se acepta una sucesión de piezas que ese jugador gana; si no, se prueba otra parecida. Los turnos que gasta son la referencia. No es el mínimo posible, por eso las estrellas dejan margen.
      • 
      
    • Las pistas usan el mismo jugador, pero mirando además cómo colocaría la pieza siguiente, y te dicen la casilla (o si conviene pasar antes por el cesto).
      • 
      
    • Las piezas no se guardan, se calculan: la pieza número k de una partida sale de la semilla y de k, así que se puede conocer cualquiera de la cola sin repetir las anteriores y deshacer nunca cambia lo que viene.
      • 
      
    • El mismo reto para todos: el reto diario convierte la fecha en una semilla (hash FNV-1a). Para que dé el mismo resultado en cualquier versión de Python, el generador de números aleatorios (mulberry32) está escrito dentro del propio archivo en lugar de usar el módulo random.
      • 
      
    • Python en el navegador: Pyodide ejecuta Python compilado a WebAssembly. script.js carga codigo.py, llama a sus funciones y recibe el estado como texto JSON.
      • 
      
    • Guardado: el reto del día guarda solo la lista de acciones y las pistas gastadas, y se reconstruye repitiéndolas, así que recargar la página no pierde el progreso.
      • 
      
    • Accesibilidad: las piezas se distinguen por la forma y el número, cada casilla tiene un nombre para lectores de pantalla (con lo que se fundiría si pones ahí la pieza actual) y se puede jugar solo con teclado.
      • 
    
    
  
    

  
    
    
    Originalidad
    
    
    Colocar piezas y fundir grupos de tres iguales es una mecánica genérica y de uso libre. El nombre, el tema del huerto, la cola visible junto al cesto, el injerto doble por grupos de cinco, la savia, las piedras que se deshacen, las pistas, las estrellas, los textos y el diseño son propios; no se ha copiado ningún juego, personaje, imagen ni sonido de terceros. Todo se dibuja con CSS. Como motor de Python solo se usa Pyodide, cargado desde su CDN.
