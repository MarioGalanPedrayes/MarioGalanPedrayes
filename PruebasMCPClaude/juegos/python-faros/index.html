    Qué se busca con esta página
    
    
    Esta práctica quiere mostrar que un juego completo puede tener toda su lógica en Python y publicarse como una web estática, sin servidor. La parte visual (HTML, CSS y un poco de JavaScript) se limita a dibujar el tablero y a avisar a Python de lo que hace la persona que juega.
    
    
    También es un ejercicio de diseño de reglas: pocas piezas, una regla que se entiende en un minuto y suficiente profundidad para que deducir sea la parte divertida. Una partida dura unos minutos, por eso encaja bien como reto diario.
    
  
    

  
    
    
    Cómo está hecho
    
    
      
      
    • codigo.py contiene las reglas: generar el código, evaluar cada intento, gastar sondas, calcular la puntuación, el texto para compartir y la racha de días.
      • 
      
    • El mismo código para todos: el reto diario usa la fecha (por ejemplo 20261103) como semilla. Para que dé el mismo resultado en cualquier versión de Python, el generador de números aleatorios (mulberry32) está escrito dentro del propio archivo en lugar de usar el módulo random.
      • 
      
    • Python en el navegador: Pyodide ejecuta Python compilado a WebAssembly. script.js carga codigo.py, llama a sus funciones y recibe el estado como texto JSON.
      • 
      
    • Guardado: la partida del día se guarda en el navegador y se reconstruye repitiendo los intentos, así que recargar la página no pierde el progreso.
      • 
      
    • Accesibilidad: cada símbolo tiene forma y color distintos (no depende solo del color), los botones tienen nombre para lectores de pantalla y se puede jugar solo con teclado.
      • 
    
    
  
    

  
    
    
    Originalidad
    
    
    Las reglas de deducción de códigos son una mecánica de juego genérica y de uso libre. El nombre, los símbolos, los textos y el diseño son propios y no se ha copiado ningún juego, personaje, imagen ni sonido de terceros: todo se dibuja con texto y CSS. Como motor de Python solo se usa Pyodide, cargado desde su CDN.
