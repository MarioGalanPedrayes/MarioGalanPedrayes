Cómo se juega

    
    
      
  1. Cada troje cabe 4 fichas, apiladas de abajo arriba. Solo se puede coger lo de arriba.
    2. 
      
  2. Al mover, pasan al destino las fichas iguales que hay pegadas arriba del origen, las que quepan. El destino debe estar vacío o tener arriba una ficha igual.
    3. 
      
  3. Un troje lleno de fichas iguales se sella solo y ya no se toca.
    4. 
      
  4. En el modo difícil un troje tiene candado (🔒 marcado con el texto «candado»): no se puede coger de él ni poner en él hasta que selles el primer troje.
    5. 
      
  5. Ganas cuando todos los trojes están vacíos o sellados.
    6. 
      
  6. La referencia es el número de movimientos de una solución que encuentra el programa. Tres estrellas hasta un 25 % por encima, dos hasta un 75 %, una si terminas. Las pistas (3 como máximo) limitan la nota a dos estrellas. Deshacer quita el movimiento del contador.
    7. 
      
  7. El reto diario es el mismo reparto para todo el mundo ese día (siempre difícil) y cuenta para la racha. En Práctica el reparto es aleatorio y no afecta a las estadísticas.

    Qué se busca con esta página
    
    
    Esta práctica quiere mostrar que un juego completo puede tener toda su lógica en Python, incluido un solucionador, y publicarse como web estática sin servidor. El HTML, el CSS y un poco de JavaScript solo dibujan los trojes y avisan a Python de cada movimiento.
    
    
    Es también un ejercicio de diseño: un puzzle de ordenar que se entiende en un minuto, cabe en una sesión corta y ofrece el mismo reto a todo el mundo cada día.
    
  
    

  
    
    
    Cómo está hecho
    
    
      
      
    • codigo.py contiene las reglas: generar el reparto, validar y aplicar movimientos, sellar trojes, el candado, deshacer, las pistas, las estrellas, el texto para compartir y la racha de días.
      • 
      
    • Siempre tiene solución: cada reparto se comprueba con un solucionador (búsqueda A* ponderada, que prueba movimientos legales y descarta estados repetidos). Solo se acepta si encuentra salida, y su longitud es la referencia. No garantiza el mínimo absoluto, por eso las estrellas dejan margen.
      • 
      
    • Las pistas usan el mismo solucionador desde la posición actual y te dicen el primer movimiento de la salida que encuentra.
      • 
      
    • El mismo reparto para todos: el reto diario convierte la fecha en una semilla (hash FNV-1a). Para que dé el mismo resultado en cualquier versión de Python, el generador de números aleatorios (mulberry32) está escrito dentro del propio archivo en lugar de usar el módulo random.
      • 
      
    • Python en el navegador: Pyodide ejecuta Python compilado a WebAssembly. script.js carga codigo.py, llama a sus funciones y recibe el estado como texto JSON.
      • 
      
    • Guardado: el reto del día guarda solo la lista de movimientos y las pistas gastadas, y se reconstruye repitiéndolos, así que recargar la página no pierde el progreso.
      • 
      
    • Accesibilidad: los productos se distinguen por la forma, los sellados y el candado tienen su propia marca de texto, cada troje tiene un nombre para lectores de pantalla y se puede jugar solo con teclado.

    Originalidad
    
    
    Repartir fichas entre recipientes por tipos es una mecánica de juego genérica y de uso libre. El nombre, el tema de la cosecha, la regla de sellado automático, el candado, las pistas, las estrellas, los textos y el diseño son propios; no se ha copiado ningún juego, personaje, imagen ni sonido de terceros. Todo se dibuja con CSS. Como motor de Python solo se usa Pyodide, cargado desde su CDN.
